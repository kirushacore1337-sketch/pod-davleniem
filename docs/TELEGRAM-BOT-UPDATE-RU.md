# Обновление Telegram-бота «Под Давлением» — пошаговая инструкция для Windows

Эта версия обновляет Telegram-бота, который работает внутри Cloudflare Worker проекта. Отдельную программу на сервере или новый Telegram-бот создавать не нужно. Токен бота, chat ID, адрес Worker и существующая база заявок сохраняются.

## Что появится после обновления

- **Новые заявки** — заявки со статусом «Новая».
- **Заявки в работе** — подтверждённые заявки. В базе это существующий статус `confirmed`, поэтому прежние данные и админка продолжают работать.
- **Выполненные** — заявки со статусом `done`.
- **Отклонённые** — заявки со статусом `cancelled`; в карточке будет отображаться причина.
- **Все заявки** — общая история с переключением страниц.
- **Статистика** — счётчики по всем статусам.
- **Помощь** — подробная справка по разделам, действиям и командам.
- **Обновить меню** — повторно показывает главное меню и свежие счётчики, а не просто отправляет подсказку.

В каждой карточке истории показываются номер, дата создания, имя, телефон, услуга, автомобиль, размер колёс, пожелания по дате и времени, комментарий и статус.

При нажатии **«Отклонить»** бот попросит написать причину отдельным сообщением. Только после этого заявка получит статус «Отклонена», а причина сохранится в D1 и будет видна в истории.

> Старые заявки, уже отменённые до этого обновления, не имеют сохранённой причины: прежняя версия бота её не запрашивала. Для таких записей будет показано «Не указана (заявка отменена до обновления бота)». Задним числом причину восстановить нельзя.

## Часть 1. Сделайте резервную копию базы заявок

Это обязательный шаг. Он сохраняет текущие заявки перед изменением структуры базы.

1. Откройте папку проекта в VS Code.
2. Откройте терминал: **Terminal → New Terminal**.
3. Перейдите в папку `worker`. Если проект находится на рабочем столе в `pod-davleniem`, команда будет такой:

```powershell
cd "$HOME\Desktop\pod-davleniem\worker"
```

Если проект лежит в другом месте, откройте папку `worker` в проводнике, нажмите адресную строку, скопируйте путь и используйте его в команде `cd`.

4. Убедитесь, что в `worker/wrangler.toml` указаны прежние `database_name` и настоящий `database_id` вашей существующей D1. **Не создавайте новую базу и не заменяйте ID на значение из примера.**
5. Выполните резервный экспорт:

```powershell
npx wrangler d1 export pod-davleniem-db --remote --output .\backup-before-telegram-update.sql
```

Файл `backup-before-telegram-update.sql` появится в папке `worker`. Убедитесь, что он существует и имеет ненулевой размер. В нём содержатся данные клиентов (персональные данные), поэтому не отправляйте его в чаты и не загружайте в GitHub. Не удаляйте его до успешной проверки обновлённого бота.

Если Wrangler попросит авторизоваться:

```powershell
npx wrangler login
```

После авторизации снова выполните команду экспорта. Имя базы в команде должно совпадать с `database_name` в `wrangler.toml`.

## Часть 2. Перенесите обновлённые файлы в ваш рабочий проект

1. Распакуйте полученный ZIP в отдельную временную папку, например `Desktop\pod-davleniem-bot-update`.
2. В распакованном проекте найдите:
   - `worker\src\index.ts`
   - `worker\schema.sql`
   - `worker\migrations\0002_telegram_bot_history.sql`
   - `docs\TELEGRAM-BOT-UPDATE-RU.md`
3. Скопируйте эти файлы в ваш существующий проект с заменой одноимённого `worker\src\index.ts` и `worker\schema.sql`; папку `worker\migrations` скопируйте целиком.
4. Не заменяйте свой `worker\wrangler.toml`: в нём уже должны находиться ваш действующий `database_id` и настройки Worker.
5. Не удаляйте `backup-before-telegram-update.sql`.

Можно также работать прямо из распакованной новой папки, но перед этим обязательно перенесите в неё ваш настоящий `worker\wrangler.toml` из старого проекта. Не используйте конфигурацию с текстом `REPLACE_WITH_D1_DATABASE_ID`.

## Часть 3. Обновите таблицы D1

Эта операция добавляет поле для причины отклонения и таблицу временного состояния бота. Существующие заявки не удаляются и не переписываются.

1. Убедитесь, что терминал находится в папке `worker` вашего рабочего проекта.
2. Выполните миграцию **один раз**:

```powershell
npx wrangler d1 execute pod-davleniem-db --remote --file=./migrations/0002_telegram_bot_history.sql
```

3. Если Wrangler попросит подтверждение, согласитесь.
4. Проверьте, что столбец `cancel_reason` появился:

```powershell
npx wrangler d1 execute pod-davleniem-db --remote --command "PRAGMA table_info(leads);"
```

В результате должна быть строка `cancel_reason`.

5. Проверьте, что создана таблица `telegram_sessions`:

```powershell
npx wrangler d1 execute pod-davleniem-db --remote --command "SELECT name FROM sqlite_schema WHERE type='table' AND name='telegram_sessions';"
```

В результате должна появиться строка `telegram_sessions`.

**Важно:** SQL-файл миграции нельзя запускать повторно: команда `ALTER TABLE ... ADD COLUMN` добавляет столбец один раз. Если увидите ошибку `duplicate column name: cancel_reason`, не запускайте её снова. Проверьте обе структуры командами выше. Если обе уже существуют, переходите к следующему шагу.

## Часть 4. Опубликуйте обновлённый Worker

1. Не закрывая терминал, убедитесь, что вы всё ещё находитесь в папке `worker`.
2. Установите зависимости (если они ещё не установлены):

```powershell
npm install
```

3. Опубликуйте Worker:

```powershell
npx wrangler deploy
```

4. Дождитесь сообщения Wrangler об успешной публикации. Если появится ошибка, не меняйте базу и секреты наугад — скопируйте полный текст ошибки.
5. Проверьте адрес Worker, который выдал Wrangler. В браузере откройте адрес с `/health`, например:

```text
https://ИМЯ-WORKER.ВАШ-SUBDOMAIN.workers.dev/health
```

Должен вернуться JSON с `"ok": true`.

### Что делать с секретами Cloudflare

При публикации того же Worker с тем же именем его Cloudflare secrets не нужно создавать заново. Сохраните текущие значения:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `TELEGRAM_WEBHOOK_SECRET`
- `ADMIN_PASSWORD`
- `JWT_SECRET`

Не вставляйте токен бота в исходники, README, GitHub или сообщения. Не присылайте его мне.

## Часть 5. Проверьте Telegram-бота

Если адрес Worker и путь `/api/telegram/webhook` не менялись, существующий webhook обычно остаётся привязан к тому же URL — повторно устанавливать его не требуется.

1. Откройте тот же личный чат или группу администраторов, чей ID указан в Cloudflare secret `TELEGRAM_CHAT_ID`.
2. Отправьте:

```text
/start
```

3. Должно прийти главное меню и счётчики по статусам.
4. Проверьте по очереди кнопки:
   - «Новые заявки»;
   - «Заявки в работе»;
   - «Выполненные»;
   - «Отклонённые»;
   - «Все заявки»;
   - «Статистика»;
   - «Помощь»;
   - «Обновить меню».
5. В списке с большим количеством записей нажмите «Далее», затем «Назад» и «Обновить список».
6. Для проверки причины отклонения используйте тестовую заявку: нажмите в её уведомлении «Отклонить», отправьте тестовую причину и убедитесь, что она появилась в разделе «Отклонённые».

Бот обрабатывает команды только в чате, ID которого совпадает с `TELEGRAM_CHAT_ID`. Если вы используете группу, бот должен быть участником именно этой группы. Не меняйте chat ID, если текущие уведомления уже приходят в нужный чат.

## Часть 6. Добавьте список команд в меню Telegram (по желанию, но удобно)

Это настраивается в `@BotFather`, не в коде:

1. Откройте `@BotFather`.
2. Отправьте `/setcommands`.
3. Выберите своего бота.
4. Вставьте следующий список:

```text
start - Открыть главное меню
menu - Главное меню
help - Помощь по боту
new - Новые заявки
active - Заявки в работе
done - Выполненные заявки
cancelled - Отклонённые заявки
all - История всех заявок
stats - Статистика заявок
refresh - Обновить меню
cancel - Отменить ввод причины
```

После этого Telegram покажет команды в меню возле поля ввода.

## Если что-то пошло не так

### Бот не отвечает на `/start`

- Убедитесь, что пишете в тот же чат/группу, ID которого сохранён в `TELEGRAM_CHAT_ID`.
- В Cloudflare откройте Worker → Logs или в терминале из папки `worker` выполните:

```powershell
npx wrangler tail
```

- Отправьте `/start` ещё раз и посмотрите новую ошибку в логах.

### Новая заявка сохраняется на сайте, но уведомление не приходит

- Проверьте Cloudflare Worker secrets `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
- Проверьте, что бот не заблокирован и добавлен в нужную группу.
- Посмотрите логи через `npx wrangler tail`.

### В списке отклонённых не отображается причина

- Убедитесь, что миграция выполнена в **remote** D1 и в `PRAGMA table_info(leads)` присутствует `cancel_reason`.
- Помните: у старых отклонённых заявок до обновления причина не записывалась.
- При отклонении новой заявки обязательно отправьте следующее сообщение с причиной.

### Wrangler пишет, что не может найти D1

- Проверьте, что команда выполняется из папки `worker`.
- Сверьте `database_name` и `database_id` в `worker/wrangler.toml` с вашей существующей D1.
- Не запускайте `d1 create`: это создаст другую базу и бот не увидит прежние заявки.

### Можно ли вернуться назад?

Да. Сначала сохраните свежий SQL-экспорт D1. Для отката кода верните резервную копию `worker\src\index.ts` и повторно выполните `npx wrangler deploy`. Но не удаляйте новые столбец и таблицу из D1: старая версия Worker их просто не использует. Удаление структуры не нужно.
